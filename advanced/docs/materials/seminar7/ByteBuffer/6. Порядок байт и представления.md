# 6. Порядок байт и представления

## Порядок байт (`ByteOrder`)

```java
void example() {
    ByteBuffer buffer = ByteBuffer.allocate(4);
    buffer.putInt(0x01020304);
    // BIG_ENDIAN (по умолчанию): [1, 2, 3, 4]

    buffer.clear().order(ByteOrder.LITTLE_ENDIAN).putInt(0x01020304);
    // LITTLE_ENDIAN:             [4, 3, 2, 1]
}
```

| Порядок | Старший байт | Где встречается |
|---|---|---|
| `BIG_ENDIAN` (по умолчанию у любого `ByteBuffer`) | первым | сетевые протоколы («network byte order») |
| `LITTLE_ENDIAN` | последним | x86/ARM-процессоры, многие форматы файлов |
| `ByteOrder.nativeOrder()` | как у текущей машины | direct-буферы, когда данные не покидают машину |

`order()` влияет только на многобайтовые операции (`putInt`, `getLong`, ...), на одиночные байты — нет.
Если формат протокола задан в big-endian, а вы работаете с little-endian — читаете «не те» числа без
всякой ошибки.

## Представления: один блок памяти, несколько «окон»

| Метод | Что получаем | Общее | Независимое |
|---|---|---|---|
| `slice()` | кусок `[position, limit)` как новый буфер с `position = 0` | содержимое | position, limit, mark |
| `duplicate()` | копия «окна» целиком | содержимое | position, limit, mark |
| `asReadOnlyBuffer()` | то же, но запись запрещена | содержимое | position, limit, mark |
| `asIntBuffer()`, `asLongBuffer()`, ... | блок как последовательность `int`/`long` | содержимое | position, limit |

```java
void example() {
    ByteBuffer src = ByteBuffer.wrap(new byte[]{0, 1, 2, 3, 4, 5});
    src.position(2);

    ByteBuffer slice = src.slice();        // видит байты 2..5; slice.position() == 0
    slice.put(0, (byte) 99);               // меняет и src: src.get(2) == 99 — память общая

    ByteBuffer copy = src.duplicate();
    copy.position(5);                      // src.position() остаётся 2 — позиции независимы
}
```

`slice()` — основной приём разбора протоколов: отрезали заголовок или тело сообщения и отдали
дальше как самостоятельный буфер, **без копирования байтов**.
