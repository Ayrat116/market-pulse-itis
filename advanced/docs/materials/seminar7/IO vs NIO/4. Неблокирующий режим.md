# 4. Неблокирующий режим

Сетевой канал можно перевести в неблокирующий режим — тогда вызовы **не ждут**, а сразу
возвращаются с тем, что получилось:

```java
void example() throws IOException {
    SocketChannel channel = SocketChannel.open();
    channel.configureBlocking(false);

    boolean connected = channel.connect(new InetSocketAddress("localhost", 1080));
    // false: рукопожатие началось, но не закончилось — connect() не ждёт

    ByteBuffer buffer = ByteBuffer.allocate(1024);
    int read = channel.read(buffer);   // 0, если данных пока нет — а не остановка потока
}
```

| Вызов | Блокирующий режим | Неблокирующий режим |
|---|---|---|
| `connect(addr)` | ждёт установки соединения | `false`, соединение достроится позже -> `finishConnect()` |
| `read(buffer)` | ждёт данные | `0`, если пока нет; `-1` — EOF |
| `write(buffer)` | ждёт, пока запишется всё | пишет сколько влезло, остальное остаётся в буфере |

Наивное использование — **занятое ожидание** (busy-wait), и оно хуже блокировки:

```java
void antiPattern(SocketChannel channel, ByteBuffer buffer) throws IOException {
    while (channel.read(buffer) == 0) {
        // крутимся и жжём процессор, ничего не получая
    }
}
```

| Подход | Процессор | Масштаб |
|---|---|---|
| Блокирующий `read` | не тратится, поток спит | поток на соединение |
| Неблокирующий `read` в цикле | 100 % ядра впустую | опрашивать приходится каждый канал |
| Неблокирующий + `Selector` | не тратится: ОС сама будит, когда есть что делать | один поток на все каналы |

Нужен способ спросить «**какие из моих каналов готовы прямо сейчас**» — не опрашивая каждый. Это
`Selector`.
