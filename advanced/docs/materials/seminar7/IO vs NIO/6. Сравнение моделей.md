# 6. Сравнение моделей

| | `java.io` | `java.nio` + `Selector` |
|---|---|---|
| Единица работы | поток байт | буфер + канал |
| Блокировка | всегда | опционально (`configureBlocking(false)`) |
| Потоков на N соединений | N | 1 (или несколько цикл-потоков) |
| Готовность к I/O | не спрашивается — поток засыпает | спрашивается через `Selector` |
| Структура данных | `byte[]` / `char[]` | [`ByteBuffer`](../ByteBuffer/1.%20Анатомия.md) с `position`/`limit` |
| Сложность кода | линейный, простой | конечный автомат на каждое соединение |
| В проекте | `HttpUrlConnectionTInvestApiClient` | `Reactor`, готовый `HttpClient` |
| Появилось | JDK 1.0 | JDK 1.4 (NIO), 1.7 (NIO.2: `Path`, `Files`, async-каналы) |

Это одна из нескольких моделей, а не «старое vs новое»:

| Модель | Как устроена | Плата |
|---|---|---|
| Поток на соединение (`java.io`) | блокирующий код, много потоков ОС | память и планировщик на масштабе |
| Reactor (`Selector`) | один поток ждёт готовности, обрабатывает по событиям | код-автомат, нельзя блокировать в цикле |
| Proactor (`AsynchronousSocketChannel`, NIO.2) | ОС выполняет операцию целиком и вызывает обработчик по завершении | колбэки, сложная отладка |
| Виртуальные потоки (JDK 21+) | блокирующий стиль кода, но поток почти бесплатный | зависит от реализации I/O в JDK, см. [слайд 4 «Пути к Reactor»](../Путь%20к%20Reactor/4.%20Виртуальные%20потоки.md) |
