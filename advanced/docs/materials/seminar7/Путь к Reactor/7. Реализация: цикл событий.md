# 7. Реализация: цикл событий

Файл: `client/impl/reactor/Reactor.java`. Три метода несут всю идею.

## `submit` — вызывающий поток не блокируется

```java
public CompletableFuture<byte[]> submit(InetSocketAddress address, byte[] requestBytes) {
    SocketChannel channel = SocketChannel.open();
    channel.configureBlocking(false);
    channel.connect(address);                          // вернётся сразу, рукопожатие идёт в фоне

    PendingExchange exchange = new PendingExchange(channel, requestBytes);
    pendingRegistrations.add(exchange);                // кладём в очередь регистрации
    selector.wakeup();                                 // будим цикл, если он спит в select()
    return exchange.future;                            // результат придёт позже
}
```

| Деталь | Зачем |
|---|---|
| Очередь `pendingRegistrations` + `wakeup()` | регистрировать канал из чужого потока, пока цикл спит в `select()`, небезопасно; цикл сам заберёт канал из очереди |
| Возвращаем `CompletableFuture` | вызывающий код решает, ждать (`join`) или навесить продолжение |

## `runLoop` — один поток на все соединения

```java
private void runLoop() {
    while (running) {
        registerPending();                             // забрать новые каналы из очереди
        selector.select();                             // ждать готовности хотя бы одного
        for (SelectionKey key : selector.selectedKeys()) {
            dispatch(key);                             // обработать готовое событие
        }
        selector.selectedKeys().clear();
    }
}
```

## `dispatch` — что делать с готовым каналом

```java
if (key.isConnectable()) {
    channel.finishConnect();
    key.interestOps(SelectionKey.OP_WRITE);            // соединились -> пишем запрос
} else if (key.isWritable()) {
    channel.write(exchange.requestBuffer);
    if (!exchange.requestBuffer.hasRemaining()) {
        key.interestOps(SelectionKey.OP_READ);         // запрос дописан -> ждём ответ
    }
} else if (key.isReadable()) {
    int read = channel.read(buffer);
    if (read == -1) {                                  // сервер закрыл соединение = ответ получен
        exchange.future.complete(exchange.responseBuffer.toByteArray());
    }
}
```

| Особенность | Комментарий |
|---|---|
| `write` может записать **не всё** | поэтому проверяем `hasRemaining()` и остаёмся в `OP_WRITE`, пока буфер не опустеет |
| `read` может вернуть часть ответа | копим в `responseBuffer`, завершаем только по `-1` |
| Ошибка `IOException` в любой ветке | `failAndClose` закрывает канал и завершает `future` исключением |
