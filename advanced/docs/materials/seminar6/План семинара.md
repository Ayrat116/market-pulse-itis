# План семинара 6. Stream API, Spliterator & Parallel Streams, Gatherer API

Порядок — как в презентации семинара. Материалы и код этой директории размечены по тем же четырём этапам.

## Этап 1. Stream API

Что такое стрим, как его создать, какие операции над ним можно выполнять и что делать с результатом.

- Как создать: из коллекции, из массива, фабриками (`Stream.of`/`empty`/`builder`), `generate`/`iterate`,
  библиотеками (`Files.lines`).
- Промежуточные операции: `filter`, `map`, `peek`, `distinct`, `skip`/`limit`, `flatMap`, `sorted`.
- Терминальные операции: `forEach`, `collect`, `reduce`, `findFirst`/`findAny`, `count`, `max`/`min`,
  `anyMatch`/`allMatch`/`noneMatch`.
- «Что ещё важно знать»: элементы идут по этапам по одному, Lazy, примитивные стримы без боксинга, `.toList()`
  (Java 11+), одноразовость стримов, `collect` заслуживает отдельного изучения.

Материал: [«Stream API»](./Stream%20API.md). Живой код — задача «постраничный перебор внешнего сервиса» на
`Stream.iterate`/`takeWhile`/`flatMap`: `demo/StreamGeneratorsDemo.java`.

## Этап 3. Spliterator и параллельные стримы — на сколько серьёзный буст?

- `Spliterator` = `tryAdvance` + `trySplit`: используется под капотом `Stream API`, и в последовательном, и в
  параллельном режиме. `trySplit()` делит пополам — возвращает новую **левую** часть, у себя оставляет **правую**.
- Самописный `Spliterator<T>` над источником с произвольным доступом: `spliterator/ArraySpliterator.java`,
  сравнение со встроенным — `demo/SpliteratorDemo.java`.
- `StreamParallelBenchmark`: когда параллелизм окупается, а когда накладные расходы перекрывают выигрыш.

Материал и результаты: [«Spliterator и параллельные стримы»](./Spliterator%20и%20параллельные%20стримы.md).

## Этап 4. Gatherer API — когда обычного Stream API уже мало

- Четыре метода: `initializer()`, `integrator(state, element, downstream)` (возвращает `boolean`, как
  `Spliterator.tryAdvance()`), `combiner(state1, state2)` (для параллельных стримов, необязателен),
  `finisher(state, downstream)` (необязателен).
- Реальная задача: разброс цены (`max - min`) в скользящем окне из `N` — `gather/SlidingSpreadGatherer.java`,
  команда `history TICKER --spread --sma K`.
- Встроенные фабрики (`windowFixed`, `windowSliding`, `scan`, `mapConcurrent`) и ещё один кастомный gatherer
  (скользящее среднее, `gather/MovingAverageGatherer.java`) — `demo/GathererDemo.java`.

Материал: [«Gatherer API»](./Gatherer%20API.md).
